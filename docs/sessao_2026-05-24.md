## 2. Renomeação de Colunas para snake_case

Todas as colunas do PostgreSQL foram renomeadas de UPPERCASE/camelCase para snake_case.
Motivação: PostgreSQL trata identificadores sem aspas como lowercase — manter UPPERCASE
exigiria aspas em todo lugar, gerando erros difíceis de rastrear.

## 5. Frontend — Módulo Recepção

### Arquivo: `frontend/src/pages/Recepcao.jsx`

**Funcionalidades:**
- Busca automática por CPF (11 dígitos) ou CNS (15 dígitos) com debounce 300ms
- Pré-preenchimento do formulário ao encontrar paciente existente
- Criação de novo paciente se não encontrado
- Campos de texto convertidos para MAIÚSCULAS automaticamente
- Validação: nome obrigatório, sexo obrigatório, CPF ou CNS válido
- Boletim A4 imprimível (campo `.no-print` oculta interface na impressão)
- Seletor de procedência na sidebar

**Modo edição** (ativado pelo Histórico):
- Recebe prop `edicao: { atendimentoId, documento, procedencia, data, hora }`
- Pré-carrega paciente via `autoBusca(edicao.documento)`
- Botão muda para "Salvar Alterações"
- Botão "Limpar" vira "← Voltar ao Histórico"
- Chama `atualizarAtendimento` + `atualizarPaciente` ao salvar

**Bug corrigido — TDZ (Temporal Dead Zone):**
Um `useEffect` que referenciava `autoBusca` foi colocado antes da declaração
`const autoBusca = useCallback(...)`. Em JavaScript, `const` não sofre hoisting
de valor, então a referência a `autoBusca` na dependency array lançava
`ReferenceError: Cannot access 'autoBusca' before initialization`.
**Correção:** o `useEffect` de edição foi movido para depois da declaração do `useCallback`.

## 9. Correções de UX — Busca por CPF/CNS

### Problema
Ao digitar um CPF ou CNS não cadastrado, o backend retornava 404.
O Axios trata 404 como exceção, então o código caía no bloco `catch` e exibia
"Erro ao buscar" em vez de indicar que é um novo paciente.

Além disso, quando o CPF/CNS digitado era inválido (dígito verificador errado),
o erro aparecia apenas dentro do campo do formulário — o badge do header não
mostrava nada.

### Correção em `Recepcao.jsx`

**`autoBusca`** — trata 404 separadamente:
```js
} catch (err) {
  if (err?.response?.status === 404) {
    if (!pacienteEncontradoRef.current) setMsg("+ Novo paciente");
  } else {
    setMsg("Erro ao buscar");
  }
}
```

**`handleCPFChange` / `handleCNSChange`** — propaga validação para o badge:
```js
if (raw.length === 11 && !validarCPF(raw)) {
  setErroCpf("CPF inválido");
  setMsg("CPF inválido");   // aparece no header também
  return;                   // não dispara busca com CPF inválido
}
```

### Comportamento final

| Situação | Badge header |
|----------|-------------|
| CPF/CNS inválido | Vermelho — "CPF inválido" / "CNS inválido" |
| CPF/CNS válido, não cadastrado | Neutro — "+ Novo paciente" |
| CPF/CNS válido, encontrado | Verde — "✓ Paciente encontrado" |
| Erro de rede/servidor | Vermelho — "Erro ao buscar" |
