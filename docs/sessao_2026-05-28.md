## 4. Fix de Duplo Registro Acidental

### Problema
Após clicar "Registrar Atendimento" com sucesso, o botão continuava ativo. Se a
atendente clicasse novamente sem limpar, criava um segundo atendimento idêntico.
O backend aceita sem reclamar (comportamento correto — paciente pode ser atendido
várias vezes, mas não no mesmo clique).

### Correção — `frontend/src/pages/Recepcao.jsx`

```jsx
const [registrado, setRegistrado] = useState(false);

// Após sucesso no registro:
setMsg("✓ Registrado!");
setRegistrado(true);     // ← bloqueia o botão

// No handleLimpar:
setRegistrado(false);    // ← desbloqueia para próximo paciente

// No botão:
disabled={loading || registrado}
```

**Comportamento:** botão desabilitado após "✓ Registrado!" até clicar "Limpar".
Modo de edição não é afetado (`setRegistrado(true)` só roda no bloco `else`).

## 5. Preparação para Produção

### 5.1 Backend — `backend/app/main.py`

| Mudança | Detalhe |
|---------|---------|
| `GZipMiddleware` | Comprime respostas JSON e texto >= 1 KB |
| CORS dinâmico | Lê `settings.CORS_ORIGINS` do `.env` (padrão `["*"]`) |
| `StaticFiles` | Serve `frontend/dist/assets/` e `frontend/dist/img/` |
| SPA fallback | `/{path}` → `index.html` se arquivo não existir |
| Docs ocultos | `/docs` e `/redoc` desaparecem quando `ENVIRONMENT=production` |

O backend serve o frontend diretamente. **Nenhum Vite dev server em produção.**

### 5.2 Config — `backend/app/core/config.py`

```python
CORS_ORIGINS: list[str] = ["*"]
```

Configurável via `.env`: `CORS_ORIGINS=["http://192.168.1.100:8001"]`

  minify: "esbuild",
  rollupOptions: {

}

Build executado: 3 chunks, ~229 KB total (gzip: ~75 KB).

## 7. Decisão: sem Docker em produção

PostgreSQL nativo é melhor para PC de recepção hospitalar Windows 24h:

| | Docker | PostgreSQL nativo |
|---|--------|-------------------|
| RAM extra | ~500 MB (Docker Desktop) | Zero |
| Pontos de falha | Docker Desktop → WSL2 → Container → PG | Só o PostgreSQL |
| Auto-start | Docker Desktop precisa abrir primeiro | Serviço Windows nativo |
| Manutenção | Alguém pode fechar o Docker sem querer | Invisível |

Docker faz sentido em servidor Linux com múltiplos serviços — não em PC Windows
de recepção onde estabilidade e simplicidade são prioridade.
