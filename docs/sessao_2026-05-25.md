## 4. Novo Endpoint: Busca Agrupada de Pacientes

### Problema original

`GET /api/v1/recepcao/` retornava uma linha por atendimento. Pacientes com múltiplos atendimentos poluíam a listagem.

### Solução

Novo endpoint: **`GET /api/v1/recepcao/pacientes/agrupado`**

Retorna pacientes únicos com estatísticas agregadas:

```json
{
  "items": [
    {
      "paciente_id": 1,
      "nome": "MARIA SILVA",
      "num_cpf": "12345678901",
      "cns": "123456789012345",
      "dtnasc": "19900101",
      "total_entradas": 7,
      "ultima_data": "2026-05-24T14:30:00"
    }
  ],
  "total": 1,
  "page": 1,
  "page_size": 20,
  "pages": 1
}
```

### O que foi criado/modificado:

| Arquivo | Mudança |
|---------|---------|
| `schemas/recepcao.py` | Novo schema `PacienteAgrupadoResponse` |
| `repositories/recepcao_repository.py` | Novos métodos `search_grouped_by_patient()` e `count_grouped_by_patient()` com JOIN + GROUP BY + COUNT + MAX |
| `services/recepcao_service.py` | Novo método `listar_agrupado()` |
| `api/v1/endpoints/recepcao.py` | Novo endpoint `GET /pacientes/agrupado` |

### Query SQL gerada:

```sql
SELECT recepcao_atendimentos.paciente_id,
       pacientes.nome,
       pacientes.num_cpf,
       pacientes.cns,
       pacientes.dtnasc,
       COUNT(recepcao_atendimentos.id) AS total_entradas,
       MAX(recepcao_atendimentos.data_atendimento) AS ultima_data
FROM recepcao_atendimentos
JOIN pacientes ON pacientes.id = recepcao_atendimentos.paciente_id
WHERE UPPER(pacientes.nome) LIKE :termo
   OR pacientes.num_cpf LIKE :termo
   OR pacientes.cns LIKE :termo
GROUP BY paciente_id, pacientes.nome, pacientes.num_cpf, pacientes.cns, pacientes.dtnasc
ORDER BY ultima_data DESC
```

### Problemas encontrados na migração de atendimentos

| Tentativa | Problema | Solução |
|-----------|----------|---------|
| 1ª | `nome` VARCHAR(50) curto demais | Aumentado para VARCHAR(100) |
| 2ª | `numpcn` VARCHAR(20) curto | Aumentado para VARCHAR(100) |
| 3ª | `dtnasc` com formato `91983-06-05` quebrava parsing | Parsing mais robusto (limpa não-dígitos, trunca para 8) |
| 4ª | `data_atendimento` NOT NULL com valores NULL no SQLite | Skip de registros sem data |
| 5ª | asyncpg exige `datetime`, não string ISO | Converter para `datetime.fromisoformat()` |
| 6ª | JOIN com OR gerava 363k linhas (cartesian product) | Dedup com `vistos` set + `p.cpf AS p_cpf` |
| 7ª | Formato da data no SQLite é `YYYY-MM-DD`, script esperava `DD/MM/YYYY` | Corrigido para aceitar ambos os formatos |
