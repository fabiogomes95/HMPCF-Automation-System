## 1. Script de Migração Profissional (`migrate_to_postgres.py`)

### Problema dos scripts anteriores

| Script | Problema |
|--------|----------|
| `migrate_to_postgres.py` (antigo) | Colunas com aspas/maiúsculas (`"CNS"`, `"NUM_CPF"`) não batiam com o modelo SQLAlchemy |
| `migrate_v2.py` | Senha hardcoded (`"hmpcf2024"`), path do SQLite errado |
| `recreate_pacientes.py` | Senha hardcoded, sem leitura de `.env` |

### Solução — reescrita completa

Arquivo: `hmcpf-system/migrate_to_postgres.py`

**Melhorias implementadas:**

| Feature | Como foi feito |
|---------|---------------|
| SQLite read-only | URI `file:///...?mode=ro` — escrita lança `OperationalError` |
| Credenciais seguras | Exclusivamente via `.env` / variáveis de ambiente |
| Colunas corretas | Minúsculas exatas do modelo SQLAlchemy |
| Todos os campos | Inclui `ibge`, `ceppcn`, `co_lograd`, `nacionalidade`, `naturalidade` |
| Deduplicação | Carrega CPFs/CNSs do PostgreSQL antes, filtra duplicatas |
| Acesso seguro a colunas | `_row_get()` com fallback — não quebra se coluna não existir |
| Batch insert + fallback | `execute_values` em lote; erro → inserção individual para isolar |
| Validação final | Compara contagens SQLite vs PostgreSQL |
| CLI | `--dry-run` e `--truncate` |

**Resultado do dry-run (pré-execução):**
- 30.496 registros lidos do SQLite
- 29.235 únicos para migrar
- 1.261 duplicatas detectadas
- 0 erros

## 2. Correções nas Colunas BPA

### Problema

Vários campos com defaults incorretos ou ausentes em todo o stack.

### Correções aplicadas

#### `ibge` — código IBGE errado

| Local | Antes | Depois |
|-------|-------|--------|
| `migrate_to_postgres.py` | `"240390"` | `"240360"` |
| `models/paciente.py` | `server_default="240390"`, `String(6)` | `server_default="240360"`, `String(6)` |
| `schemas/paciente.py` (Create) | `Optional[str] = None` | `str = Field(default="240360")` |

#### `ceppcn`, `co_lograd`, `nacionalidade` — viravam NULL

`PacienteCreate` tinha esses campos como `Optional[str] = None`. O serviço fazia `Paciente(**data.model_dump())` passando `None` explicitamente, o que anulava os `server_default` do PostgreSQL.

**Solução:** defaults Python no schema:
```python
ceppcn:       str = Field(default="59575000")
co_lograd:    str = Field(default="081")
nacionalidade: str = Field(default="010")
```

#### `naturalidade` — campo ausente no schema e no frontend

Campo existia no modelo mas nunca chegava via API nem era exibido/salvo corretamente.

**Adicionado em:**
- `PacienteCreate`: `naturalidade: Optional[str] = None`
- `PacienteUpdate`: `naturalidade: Optional[str] = None`

## 3. Correção NATURALIDADE na Ficha A4

### Problema

O campo "NATURALIDADE" na Ficha A4 (`BoletimA4.jsx`) tinha `name="nacionalidade"` — sobrescrevia o código de nacionalidade ("010") com texto livre da cidade de nascimento.

### Correção

**`BoletimA4.jsx`:**
```jsx
// ANTES (errado)
<input type="text" name="nacionalidade" value={form.nacionalidade || ""} ... />

// DEPOIS (correto)
<input type="text" name="naturalidade" value={form.naturalidade || ""} ... />
```

**`Recepcao.jsx`:**

| Campo | Antes | Depois |
|-------|-------|--------|
| `vazio.naturalidade` | ausente | `""` |
| `vazio.nacionalidade` | `""` | `"010"` (fixo) |
| `camposTexto` | incluía `"nacionalidade"` | substituído por `"naturalidade"` |
| `autoBusca` | não carregava `naturalidade` | `naturalidade: p.naturalidade \|\| ""` |
